CORRECTIFS À FAIRE DANS CE BATCH

==================================================
P1 — FALLBACK INCOMPLET APRÈS AJOUT DE canCollect
==================================================

PROBLÈME
Dans PublicMarketplace.tsx, le fallback de fetchMarketFeeBox retourne encore :
{ gold: 0 }
alors que le type réel attendu est maintenant :
{ gold: number; canCollect: boolean }

RISQUE
Si la requête fee-box échoue, rmFeeBox.canCollect devient undefined.
Le bloc caisse locale peut alors disparaître silencieusement de manière incohérente.

CORRECTION ATTENDUE
Remplacer le fallback par :
{ gold: 0, canCollect: false }

IMPORTANT
Ne touche pas à la logique générale de chargement.
Corriger uniquement ce fallback.

==================================================
P4 — FUITE D’INFORMATION SUR GET /fee-box/:cityId
==================================================

PROBLÈME
La route GET /api/market/fee-box/:cityId retourne actuellement :
{ gold, canCollect }

Même si canCollect === false, l’utilisateur peut quand même connaître le montant réel de la caisse locale.

OBJECTIF
Conserver le booléen canCollect, mais ne pas exposer le montant réel aux non-autorisés.

CORRECTION MINIMALE ATTENDUE
Dans GET /fee-box/:cityId :

- si l’utilisateur est autorisé à collecter :
  retourner le vrai montant + canCollect: true

- si l’utilisateur n’est PAS autorisé :
  retourner
  { gold: 0, canCollect: false }

IMPORTANT
Ne pas changer POST /fee-box/:cityId/collect
Ne pas changer collectFeeBox(...)
Ne pas changer la logique métier d’autorisation
On masque seulement la lecture du montant aux non-autorisés.

P3 — pendingFeeAppliesAt! NON SÉCURISÉ CÔTÉ UI
==================================================

PROBLÈME
Dans PublicMarketplace.tsx, l’affichage du fee pending utilise encore :
rmGuild.pendingFeeAppliesAt!

CORRECTION ATTENDUE
Ne rendre la ligne pending que si :
- rmGuild.pendingFeeBps != null
ET
- rmGuild.pendingFeeAppliesAt != null

IMPORTANT
Correctif strictement minimal.
Ne pas refaire le bloc UI.
Ne pas changer le sens du message.
Seulement sécuriser le rendu.
