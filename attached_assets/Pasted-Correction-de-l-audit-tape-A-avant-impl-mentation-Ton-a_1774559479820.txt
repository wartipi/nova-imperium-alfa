Tu proposes un `console.warn` non bloquant si `postEconomyTick(currentTurn)` échoue.
Ce point doit être corrigé.

- le tour client avance
- mais le tick économique serveur du tour courant peut être perdu

Je veux donc la règle suivante :
- si le joueur a une faction :
  - `postEconomyTick(currentTurn)` doit réussir avant `endTurn()`
- si le tick échoue :
  - ne pas appeler `endTurn()`
  - lancer `hydrateCitiesFromServer()` pour limiter les divergences après `processTurn()`
- si le joueur n’a pas de faction :
  - skip du tick
  - `endTurn()` autorisé
