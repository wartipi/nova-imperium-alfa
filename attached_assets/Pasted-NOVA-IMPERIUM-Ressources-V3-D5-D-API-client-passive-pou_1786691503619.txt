À FAIRE

1. Ajouter les types client pour la route

Dans `client/src/lib/api/citiesApi.ts` ou fichier cohérent existant, ajouter :

type RecruitmentCostResource =
  | "food"
  | "wood"
  | "stone"
  | "common_metals"
  | "common_textiles"
  | "labor_contracts"
  | "basic_equipment";

type RecruitmentResourceCost = Partial<Record<RecruitmentCostResource, number>>;

interface RecruitmentMissingResource {
  resource: RecruitmentCostResource;
  required: number;
  available: number;
  shortage: number;
}

interface StartRecruitmentSuccess {
  ok: true;
  cityId: number;
  unitType: string;
  production: {
    type: "unit";
    name: string;
    cost: number;
    progress: number;
  };
  debited: RecruitmentResourceCost;
}

Adapter les noms si les conventions existantes du fichier sont différentes.

2. Ajouter une fonction API passive

Créer :

apiStartRecruitment(cityId: number, unitType: string): Promise<StartRecruitmentSuccess>

Elle doit appeler :

POST /api/cities/${cityId}/start-recruitment

Body :

{
  unitType
}

Comportement :
- envoyer Content-Type: application/json ;
- utiliser les mêmes options d’auth/credentials que les autres appels du fichier ;
- si réponse OK : retourner le JSON typé ;
- si erreur :
  - lire le JSON si possible ;
  - préserver `error`, `message`, `missing`;
  - throw une erreur lisible ;
  - idéalement attacher les données brutes à l’erreur si le pattern existant le permet.
