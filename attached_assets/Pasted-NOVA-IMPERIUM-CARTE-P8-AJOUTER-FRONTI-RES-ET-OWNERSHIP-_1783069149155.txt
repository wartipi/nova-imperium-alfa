1. Les territoires contrôlés / revendiqués déjà connus.

ÉTAPE 1 — AUDIT DES DONNÉES OWNERSHIP DISPONIBLES

Inspecter :

* GameCanvas.tsx
* PixelMapRenderer.ts
* UnifiedTerritorySystem.ts
* stores déjà utilisés par GameCanvas
* données de territoires déjà chargées côté client

Identifier précisément :

* où se trouve l’owner d’une tuile :

  * tile.ownerId
  * tile.ownerType
  * tile.factionId
  * territory owner déjà chargé
  * autre champ existant
* comment le mode stratégique dessine déjà les frontières / territoires
* si les données territory sont passées séparément ou incluses dans mapData
* comment distinguer :

  * sans propriétaire
  * joueur
  * faction
  * colonie
  * propriétaire inconnu

Important :

* ne pas inventer de nouveau champ serveur
* ne pas faire de nouveau fetch
* ne pas modifier backend
* ne pas dupliquer la logique ownership si une donnée existe déjà

ÉTAPE 2 — TYPES

Étendre PixelMapTile uniquement avec les champs déjà réellement disponibles.

Exemple acceptable si compatible :

export interface PixelMapTile {
x?: number;
y?: number;
terrain: string;
resource?: string | null;
resourceType?: string | null;
discovered?: boolean;
explored?: boolean;
ownerId?: string | number | null;
ownerType?: string | null;
factionId?: string | number | null;
cityId?: string | number | null;
buildingType?: string | null;
buildingId?: string | number | null;
}

Étendre PixelMapRenderOptions si nécessaire :

showOwnership?: boolean;
showBorders?: boolean;
getTileOwner?: (x: number, y: number, tile: PixelMapTile) => string | number | null | undefined;
getOwnerColor?: (ownerId: string | number | null | undefined) => string | null;

Valeurs par défaut :

* showOwnership true
* showBorders true

Si GameCanvas possède déjà une façon de calculer la couleur territoire :

* réutiliser cette logique
  Sinon :
* créer un mapping déterministe local simple basé sur ownerId
* ne pas modifier les systèmes existants

ÉTAPE 3 — COUCHES VISUELLES

Ajouter dans PixelMapRenderer.ts des fonctions internes, par exemple :

* drawOwnershipOverlay(...)
* drawTerritoryBorders(...)

Ne pas exporter inutilement.

Rendu recommandé :

1. Ownership intérieur :

   * voile très léger de couleur propriétaire
   * alpha faible
   * ne doit pas cacher le terrain Pixel HD
   * seulement sur tuile visible
   * ne pas afficher sous fog total

2. Frontières :

   * ligne plus claire ou plus saturée sur les arêtes où le voisin a un owner différent
   * largeur raisonnable
   * style médiéval/stratégique discret
   * doit rester lisible sans dominer la carte

ÉTAPE 4 — DÉTECTION DES FRONTIÈRES

Déterminer les voisins hex selon la même convention que la carte actuelle.

Important :

* respecter la géométrie hex à colonnes décalées utilisée par GameEngine :

  * x pair / impair influence y
* ne pas utiliser une grille carrée
* ne pas tracer une frontière entre deux tuiles du même owner
* tracer une frontière si :

  * tuile A a owner
  * voisin B absent ou owner différent
  * option showBorders active
  * tuile A visible

Si le voisin est non visible sous fog total :

* ne pas révéler son owner
* tracer seulement une frontière extérieure discrète si la tuile visible elle-même a un owner, sans exposer l’identité du voisin caché

ÉTAPE 5 — VISIBILITÉ / FOG

Règles strictes :

* fog total masque ownership et frontières
* fog ring peut assombrir ownership/frontières
* ne jamais révéler un owner caché par l’exploration
* ne jamais afficher couleur propriétaire sur une tuile non visible
* ne pas modifier la logique de vision

Le renderer doit seulement consommer :

* isHexVisible
* isHexInFogRing
* callbacks/données ownership existants

ÉTAPE 6 — GAMECANVAS

Dans GameCanvas.tsx :

* transmettre showOwnership: true
* transmettre showBorders: true
* transmettre les données owner déjà disponibles
* ne pas faire de nouvel appel réseau
* ne pas créer de nouveau store global
* ne pas modifier les règles existantes

Si ownerId est déjà dans mapData :

* PixelMapRenderer peut l’utiliser directement

Si ownership vient d’une autre structure chargée :

* créer un callback getTileOwner qui lit cette structure existante

ÉTAPE 8 — COULEURS

Utiliser une couleur déterministe par ownerId si aucune palette officielle n’est disponible.

Règles :

* pas de couleur trop saturée
* alpha faible pour overlay
* ligne frontière plus visible mais pas agressive
* pas de conflit avec sélection
* pas de conflit avec fog

Exemple :

* hash ownerId → hue
* hsl(hue, 45%, 55%)
* overlay alpha 0.12 à 0.20
* border alpha 0.65 à 0.85

* ne rien dessiner
* pas de log spam
