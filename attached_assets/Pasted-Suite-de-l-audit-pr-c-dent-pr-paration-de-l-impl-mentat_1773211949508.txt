Suite de l’audit précédent : préparation de l’implémentation de la migration du vieux mode MJ client.

Le diagnostic est validé.

Le vieux mode MJ est actuellement :

- un toggle Zustand local (isGameMaster)
- non connecté au rôle serveur
- accessible via des conditions hardcodées sur les usernames
- utilisé dans plusieurs composants pour bypass gameplay et affichage

La direction validée est :

- supprimer ce toggle comme source de vérité
- utiliser le rôle serveur authentifié (role === 'admin')
- migrer progressivement les comportements MJ vers des privilèges admin cohérents

Important : correction architecturale supplémentaire

Lors de l’audit précédent, une proposition suggérait de lire directement le rôle via useAuth() dans GameEngine.ts.

Ce n’est pas acceptable.

GameEngine.ts est un moteur non-React et ne doit pas dépendre de hooks React.

La bonne architecture est :

React lit le rôle utilisateur → React injecte l’information admin dans le moteur → le moteur utilise cette information.

Donc :

GameEngine ne doit pas appeler useAuth().
GameEngine doit recevoir un flag injecté (par exemple isAdmin).

Exemple conceptuel attendu :

Dans un composant React :

const { role } = useAuth();
gameEngine.setAdminMode(role === 'admin');

Et dans GameEngine :

this.isAdminMode = false;

setAdminMode(value) {
  this.isAdminMode = value;
}

Puis utiliser :

if (this.isAdminMode) { ... }

au lieu de isGameMaster.
