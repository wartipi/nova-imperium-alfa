CORRECTION DE RÈGLE CANONIQUE
La règle canonique correcte est :

1. Le marché est un service central.
2. La banque est un service central.
3. Les bâtiments guilde_des_marchands et bank ne créent pas ces services.
4. Ces bâtiments sont des points d’accès physiques à ces services.
5. Le joueur ne peut accéder à un service central QUE s’il est physiquement sur une case contenant le bâtiment correspondant.
6. Sans présence physique sur une case valide :
   - aucun accès au marché
   - aucun accès à la banque

IMPORTANT
Donc :
- oui au modèle “service central”
- non au modèle “accès depuis n’importe quelle ville possédée”
- le gate canonique est la position réelle du joueur sur une case équipée

ERREUR À CORRIGER
La migration précédente du marché a transformé le système en réseau global, mais a laissé l’accès dépendre d’une simple sélection de ville.
Ceci est faux au regard de la règle canonique.
Il faut remplacer ce faux accès “à distance” par un accès “depuis terminal physique”.

PRIORITÉ
Simplicité > Lisibilité > Stabilité > Compatibilité

INTERDIT
- refactor massif
- nouveau gros système
- supprimer le modèle réseau global
- réécrire tout le marché et toute la banque d’un coup sans audit
- confondre “service central” et “accès distant libre”

PHASE 2 — RÈGLE D’IMPLÉMENTATION
==================================================

Tu dois appliquer la règle suivante :

MARCHÉ
- accès autorisé seulement si le joueur est physiquement sur une case correspondant à une ville possédant guilde_des_marchands
- une fois autorisé, le carnet reste global
- le point d’accès local détermine les frais
- sans présence sur une case valide : accès refusé

BANQUE
- accès autorisé seulement si le joueur est physiquement sur une case correspondant à une ville possédant bank
- une fois autorisé, l’accès est au service bancaire central
- sans présence sur une case valide : accès refusé

IMPORTANT
Le gate doit être :
- basé sur la position réelle du joueur
- pas seulement sur ownership
- pas seulement sur cityId choisi dans l’UI

PHASE 3 — IMPLÉMENTATION MINIMALE RECOMMANDÉE
==================================================

Tu dois viser le plus petit passage propre :

1. créer un helper serveur du type :
- resolveCurrentAccessPointForPlayer(playerId, serviceType)
ou équivalent

2. ce helper doit :
- lire la position réelle du joueur
- retrouver si cette position correspond à une ville
- vérifier si cette ville possède le bâtiment requis
- retourner soit :
  - accès valide + cityId + fee context éventuel
  - soit refus clair

3. routes marché :
- ne plus dépendre de la ville arbitrairement sélectionnée par l’utilisateur pour autoriser l’accès
- la ville réellement utilisée doit être celle du point d’accès où se trouve le joueur

4. routes banque :
- appliquer la même logique

5. UI :
- ne plus présenter le service comme librement accessible depuis n’importe quelle ville
- afficher clairement :
  - accès disponible si le joueur est sur un point d’accès valide
  - sinon message de refus explicite
