Nouveau bloc de travail : correctif du déplacement admin instantané avec resynchronisation serveur.

Contexte du projet

Nova Imperium utilise un moteur d’actions persistantes côté serveur.

Le déplacement du joueur passe par :

POST /api/player/actions/move

Le pipeline normal est :

1. le client demande un déplacement
2. le serveur calcule un chemin
3. le serveur crée une action persistante
4. le serveur la stocke en base
5. le client affiche l’action en cours
6. quand l’action se complète, la position du joueur est mise à jour côté serveur

Des modifications récentes ont déjà été faites :

- le rôle "gm" a été supprimé du backend
- le backend fonctionne maintenant avec seulement :
  - admin
  - player
- les comptes admin ont un bypass timer côté serveur
- pour un compte admin, un déplacement peut donc être instantané (durationMs = 0)
- le widget "Action en cours" existe déjà dans le panneau droit sous la jauge PA

Problème observé en test réel

Lorsqu’un déplacement est tenté avec un compte admin :

- la requête de déplacement est bien envoyée
- le serveur crée bien l’action
- l’action est bien complétée immédiatement
- la position est bien mise à jour en base
- mais l’avatar à l’écran ne se déplace pas correctement

Le diagnostic précédent a déjà établi la cause :

- côté client, après une action instantanée admin, la position visuelle locale n’est pas resynchronisée
- le backend fait bien son travail
- le problème visible est donc côté client

Décision technique validée

Nous prenons la stratégie A :

Après une action instantanée admin, le client doit :
1. recharger la position réelle depuis le serveur
2. mettre à jour le rendu de l’avatar à partir de cette position serveur

Important :
nous ne voulons pas simplement appeler moveAvatarToHex() directement avec une supposition locale.

Nous voulons que la resynchronisation passe par la source de vérité serveur.

Objectif de cette tâche

Corriger le comportement du déplacement admin instantané pour que :

- le serveur reste la source de vérité
- après un move instantané admin, la position soit relue depuis le serveur
- l’avatar soit visuellement resynchronisé correctement
- le flux normal des joueurs non-admin reste inchangé

Règles de travail

Avant toute modification :

1. expliquer précisément quel point du code sera corrigé
2. expliquer comment la position sera relue depuis le serveur
3. expliquer comment le rendu local sera resynchronisé
4. attendre validation

Tu ne modifies rien avant validation.

Autres contraintes :

- ne pas refondre le pipeline de déplacement
- ne pas modifier le backend si ce n’est pas nécessaire pour ce correctif
- ne pas casser le comportement normal des joueurs
- ne pas remplacer la source de vérité serveur par un déplacement purement local
- rester sur le plus petit correctif cohérent
