OBJECTIF P11
Afficher en mode immersive les routes existantes ou chemins déjà présents dans les données client, sans créer de nouveau système.

Le rendu doit :

1. afficher les routes seulement sur les tuiles visibles ;
2. rester discret et lisible ;
3. ne pas révéler d’information sous fog total ;
4. ne pas modifier la logique de jeu ;
5. respecter la géométrie hex existante.

IMPORTANT
Ne pas inventer de routes.
Ne pas générer de routes automatiquement.
Ne pas créer de nouveau modèle de données.
Ne pas faire de nouveau fetch.
Ne pas ajouter les rivières dans ce bloc.

ÉTAPE 1 — AUDIT DES DONNÉES ROUTES DISPONIBLES

Inspecter :

* GameCanvas.tsx
* PixelMapRenderer.ts
* types de tuiles existants
* mapAdapter.ts si nécessaire
* GameEngine.ts seulement pour voir si la vue strategic affiche déjà des routes

Identifier précisément :

* si les routes existent déjà dans mapData
* nom exact du champ s’il existe :

  * road
  * hasRoad
  * route
  * roadType
  * improvementType
  * infrastructure
  * buildingType
  * autre champ réel
* si les routes sont des bâtiments/améliorations de tuiles
* si la vue strategic affiche déjà quelque chose lié aux routes
* si aucune donnée route n’existe encore

Important :

* si aucune donnée route n’existe, ne pas inventer
* produire un rapport clair indiquant que P11 ne peut pas afficher de routes réelles sans source de données
* dans ce cas, ne pas ajouter de faux rendu

ÉTAPE 2 — TYPES

Étendre PixelMapTile seulement avec les champs réellement disponibles.

Exemple autorisé uniquement si compatible avec les données réelles :

export interface PixelMapTile {
x?: number;
y?: number;
terrain: string;
resource?: string | null;
resourceType?: string | null;
discovered?: boolean;
explored?: boolean;
ownerId?: string | number | null;
ownerType?: string | null;
factionId?: string | number | null;
cityId?: string | number | null;
buildingType?: string | null;
buildingId?: string | number | null;
road?: boolean;
hasRoad?: boolean;
roadType?: string | null;
improvementType?: string | null;
}

Étendre PixelMapRenderOptions si nécessaire :

showRoutes?: boolean;
hasTileRoad?: (x: number, y: number, tile: PixelMapTile) => boolean;

Valeur par défaut :

* showRoutes true

Si les routes ne sont pas dans tile mais dans une structure séparée :

* transmettre un callback depuis GameCanvas.tsx
* ne pas créer de nouveau store
* ne pas faire de fetch

ÉTAPE 3 — VISIBILITÉ / FOG

Règles strictes :

* une route ne s’affiche jamais sur une tuile non visible
* fog total masque les routes
* fog ring peut assombrir les routes
* ne jamais révéler une route cachée
* ne pas modifier la logique d’exploration

Le renderer doit seulement consommer :

* isHexVisible
* isHexInFogRing
* données existantes de route
* callback hasTileRoad si nécessaire

ÉTAPE 4 — RENDU VISUEL DES ROUTES

Ajouter dans PixelMapRenderer.ts une fonction interne :

drawRoutesLayer(...)

Rendu recommandé :

* lignes fines style chemin de terre / pavé léger
* couleur brun/gris discret
* alpha modéré
* pas de texte
* pas d’emoji
* pas d’image externe
* compatible avec le style Pixel HD
* lisible au zoom moyen
* ne doit pas dominer terrains, frontières ou unités

La route doit idéalement connecter le centre de l’hex aux côtés qui mènent vers des voisins avec route.

Si la donnée ne permet pas de savoir les connexions :

* dessiner un petit segment ou croix discrète au centre de l’hex
* documenter la limite
* ne pas inventer de réseau complet

ÉTAPE 5 — CONNEXION HEX

Si les routes existent sur des tuiles adjacentes :

* connecter les centres des hex voisins visibles avec route
* utiliser la géométrie hex existante
* respecter colonnes décalées x pair / impair
* ne pas utiliser une grille carrée

Règles :

* tracer connexion A → B si :

  * A visible
  * B visible
  * A a route
  * B a route
* si B est sous fog total :

  * ne pas tracer vers B
  * ne pas révéler la continuité de la route

ÉTAPE 8 — FALLBACK SI AUCUNE DONNÉE ROUTE

Ne pas créer de faux système.

* éventuellement ajouter les options showRoutes / hasTileRoad prêtes pour plus tard seulement si cela reste propre et sans effet visuel
* aucun rendu visible inventé
* rapport final indiquant que P11 est bloqué côté données
