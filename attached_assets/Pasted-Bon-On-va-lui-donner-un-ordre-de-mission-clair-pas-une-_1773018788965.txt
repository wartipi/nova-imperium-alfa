# Étape 1 — Corriger le rendu du terrain `plains`

Problème identifié :

Le type de terrain `plains` existe dans :

* `TerrainType`
* `MapGenerator.ts`
* la base de données

Mais **GameEngine.ts ne contient pas la couleur associée**.

Résultat :
si la carte est chargée depuis la DB, environ **24.5 % des tuiles apparaissent grises**.

### Action

Dans **GameEngine.ts** :

1. Localiser la table de couleurs utilisée par `getTerrainColor`.
2. Ajouter l’entrée suivante :

```
plains: '#C8E6A0'
```

3. Vérifier que le type `TerrainType` accepte bien `plains`.
4. Vérifier que `plains` est correctement interprété dans toutes les fonctions visuelles.

### Résultat attendu

Les tuiles `plains` doivent apparaître **vert pâle** et non gris.

# Étape 2 — Corriger les fonctions de comptage inefficaces

Problème identifié :

Les fonctions :

* `getSegmentCount()`
* `getTileCount()`

chargent tous les IDs en mémoire puis utilisent `.length`.

C’est inefficace et inutile.

### Action

Dans **mapSegmentService.ts** :

Remplacer les requêtes existantes par un **COUNT SQL réel**.

Exemple attendu (conceptuellement) :

```
SELECT COUNT(*) FROM map_segments
SELECT COUNT(*) FROM map_tiles
```

Avec Drizzle ORM, utiliser la fonction adaptée pour retourner directement le nombre.

### Résultat attendu

Les fonctions doivent :

* retourner un nombre
* ne pas charger toute la table en mémoire
* rester compatibles avec le reste du service.

# Étape 3 — Activer le chargement de la carte depuis la base

Actuellement :

* `loadBlockFromDB()` existe
* `mapApi.ts` existe
* `mapAdapter.ts` existe
* mais **le jeu démarre encore avec la génération procédurale**.

Tu dois **brancher la base de données comme source principale de la carte**.

### Action

1. Identifier l’endroit où la carte est initialisée au démarrage du jeu.
2. Appeler :

```
loadBlockFromDB(0, 0)
```

pour charger le bloc central.

3. Conserver temporairement le fallback existant vers la génération procédurale si l’API échoue.

### Flux attendu

Initialisation du jeu :

```
start game
→ loadBlockFromDB(0,0)
→ fetch /api/map/block/0/0
→ adapter DB tiles → HexTile[][]
→ injecter dans le moteur
```

### Résultat attendu

Le jeu doit afficher la carte **chargée depuis la base de données**.
