PROBLÈME 1 — VISIBILITÉ DES FRONTIÈRES TROP RESTRICTIVE
Dans la seconde passe de renderMap(), le rendu des frontières est actuellement filtré avec :
- isInCurrentVision

Cela peut être trop restrictif visuellement.
Si une case est découverte / visible dans le modèle du joueur mais pas dans la vision immédiate, sa frontière ne sera pas dessinée.

Je veux que tu vérifies cette condition et que tu l’ajustes vers la règle la plus cohérente pour l’UX actuelle.

Objectif attendu :
- les frontières territoire doivent être visibles selon une logique cohérente avec l’affichage de la carte,
- pas uniquement selon la vision immédiate si cela coupe artificiellement le contour.

Tu dois auditer quelle condition est la plus juste parmi :
- isInCurrentVision
- isVisible
- isInCurrentVision || isInFogRing
- autre condition déjà disponible dans ce fichier

IMPORTANT :
- ne fais pas d’invention
- ne crée pas une nouvelle règle
- réutilise les callbacks de vision déjà présents dans GameEngine.ts
- choisis la plus petite correction cohérente avec le rendu existant

PROBLÈME 2 — STROKE DE GRILLE FRAGILE
Dans renderMap(), après drawHex(...), le code fait encore un simple :
- ctx.stroke()

Ce stroke dépend implicitement du path courant laissé par drawHex(...).
Or drawHex(...) contient plusieurs beginPath() internes selon :
- rivière
- sélection
- preview path
- pending destination
- autres overlays

Je veux que tu sécurises ce comportement.

OBJECTIF
Le contour gris standard de chaque hex doit être dessiné à partir d’un path hex explicite et stable,
pas à partir d’un path implicite laissé par drawHex(...).
