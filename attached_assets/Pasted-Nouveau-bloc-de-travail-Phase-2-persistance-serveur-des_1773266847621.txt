Nouveau bloc de travail : Phase 2 — persistance serveur des factions.

Contexte

Nova Imperium a déjà une base technique suffisamment propre pour attaquer le premier vrai système métier partagé du jeu.

Les éléments suivants existent déjà :

- authentification serveur réelle
- rôles serveur (admin / player)
- carte persistée en PostgreSQL
- positions joueurs persistées
- actions de déplacement persistées côté serveur
- état joueur persisté
- mode admin ON/OFF propre
- migration de l’ancien mode MJ client déjà terminée

Mais les factions restent encore un système trop local.

Constat actuel

Le système de factions vit encore essentiellement côté client.

Cela signifie que :
- la création de faction n’est pas encore un vrai fait partagé du monde serveur
- l’appartenance à une faction n’est pas encore une vérité serveur persistée
- les autres systèmes futurs (territoires, traités, diplomatie) n’ont pas encore une base politique partagée fiable

Objectif de la phase

Transformer les factions en système serveur persistant partagé.

À la fin de cette phase, on veut pouvoir dire :

- les factions sont stockées en PostgreSQL
- l’appartenance d’un joueur à une faction est stockée côté serveur
- la création de faction passe par une route authentifiée
- la lecture des factions passe par des routes serveur
- le client ne garde plus une source de vérité parallèle locale

Important :
cette phase est d’abord un audit et une proposition d’architecture.
Tu ne modifies rien avant validation.

Règles de travail

Avant toute modification :

1. auditer le système actuel de factions côté client
2. identifier précisément ce qui existe déjà côté serveur ou non
3. proposer un schéma minimal mais propre de persistance serveur
4. proposer les routes API minimales nécessaires
5. proposer comment migrer useFactions.tsx vers une source serveur
6. attendre validation

Tu ne modifies rien avant validation.

Contraintes

- ne pas toucher encore aux territoires / colonies dans cette phase
- ne pas toucher encore à la présence multijoueur
- ne pas faire de refonte totale de toute la diplomatie
- rester sur le cœur du système factions
- privilégier une architecture simple, lisible, compatible avec la suite
- citer les fichiers, stores, routes, tables exacts
- ne pas supposer l’existence d’une persistance serveur si elle n’existe pas réellement

Exigence de rigueur

- pas de formulation vague
- pas de supposition sans preuve
- distinguer clairement :
  - état actuel
  - cible minimale
  - points de migration client
  - limites restant hors périmètre
