CORRECTIFS À FAIRE DANS CE BATCH

==================================================
UX-1 — MASQUER “CHANGER %” AUX NON-AUTORISÉS
==================================================

PROBLÈME
Le champ + bouton de changement de commission est visible pour tous les joueurs ayant accès au marché.
Les non-propriétaires peuvent tenter l’action, puis le serveur renvoie 403.

OBJECTIF
Ne montrer l’UI de changement de commission qu’aux utilisateurs réellement autorisés.

RÈGLE ATTENDUE
Le bloc input + bouton “Changer %” doit être visible seulement si :
- access.isAdmin === true
OU
- le marché appartient au joueur
OU
- le marché appartient à une faction dont le joueur est membre autorisé

IMPORTANT
Privilégie la plus petite solution propre.
Si le client ne peut pas déterminer proprement le cas faction avec les infos déjà disponibles, n’invente pas une logique fragile.
Dans ce cas :
- soit tu réutilises une info déjà présente
- soit tu proposes un micro-enrichissement minimal
Mais seulement si c’est strictement nécessaire.

==================================================
UX-2 — MASQUER “VENDRE” SUR SON PROPRE ORDRE BUY
==================================================

PROBLÈME
Dans la liste des ordres BUY, le propriétaire de l’ordre voit encore le bouton “Vendre”.
En cliquant, la modale s’ouvre puis le serveur rejette avec :
“Vous ne pouvez pas remplir votre propre ordre”.

OBJECTIF
Éviter cette action inutile côté UI.

CORRECTION ATTENDUE
Dans la liste des ordres BUY :
- masquer le bouton “Vendre” si o.playerId === playerId
- conserver le bouton “Annuler” pour le propriétaire

IMPORTANT
Ne touche pas au garde serveur existant.
Le serveur doit continuer à protéger ce cas.

==================================================
UX-3 — CORRIGER MAX BUY QUI PEUT METTRE qty=0
==================================================

PROBLÈME
Le bouton Max du formulaire BUY peut fixer qty à 0 si :
transport.gold < draft.price

Cela mène ensuite à une erreur serveur “quantity doit être un entier positif”.
Le serveur a raison, mais l’UX est mauvaise.

OBJECTIF
Empêcher le bouton Max de produire un état invalide.

CORRECTION MINIMALE ATTENDUE
Choisir UNE seule de ces solutions simples :

Option A — préférée
- désactiver le bouton Max BUY si le max calculé < 1

OU

Option B
- ne rien changer visuellement mais ne jamais écrire 0
- si maxQty < 1, garder la quantité actuelle ou forcer 1

IMPORTANT
Choisir la version la plus propre et cohérente avec l’UI actuelle.
Pas de refonte.
