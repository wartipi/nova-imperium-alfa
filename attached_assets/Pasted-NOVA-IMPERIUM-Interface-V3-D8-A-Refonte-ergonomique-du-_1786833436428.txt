NOVA IMPERIUM — Interface V3-D8-A
Refonte ergonomique du panneau de gestion Ville / Territoire + accès direct depuis la carte

RÔLE
Tu es l’agent technique sur le repo Nova Imperium.
Objectif : améliorer l’ergonomie du prototype en séparant clairement la gestion des territoires et la gestion des villes, puis ajouter un accès direct à la gestion d’une ville depuis la carte.

CONTEXTE

Le panneau actuel mélange trop d’informations :
- territoires ;
- villes ;
- colonies ;
- panneaux de gestion ;
- actions de ville.

Résultat observé :
- le joueur ne sait pas clairement où cliquer ;
- les villes et territoires sont mélangés ;
- l’accès à la gestion complète d’une ville n’est pas assez direct ;
- le joueur devrait pouvoir cliquer une ville sur la carte et ouvrir directement sa gestion.

IMPORTANT

Ce bloc est UI/UX.
Ne pas modifier la logique économique.
Ne pas modifier le serveur sauf nécessité stricte pour consommer une donnée déjà existante.
Ne pas créer de migration DB.
Ne pas modifier les règles de recrutement.
Ne pas modifier les coûts/durées/stats.
Ne pas activer upkeep.
Ne pas ajouter de dépendance.
Ne pas ajouter de store.
Ne pas faire de refactor massif.

OBJECTIF GÉNÉRAL

Créer une interface plus claire avec deux niveaux :

1. Gestion des territoires
2. Gestion des villes

Et ajouter un accès direct :

Carte → clic ville → bouton “Gérer la ville” → ouverture du panneau de gestion de cette ville précise.

STRUCTURE UI SOUHAITÉE

Dans le panneau administratif principal, ajouter deux onglets principaux :

[ Territoires ] [ Villes ]

ONGLET TERRITOIRES

Objectif :
Vue macro.

Afficher une liste de territoires ou zones contrôlées, selon les données existantes.

Chaque entrée doit afficher si disponible :
- nom du territoire ;
- propriétaire/faction ;
- capitale ou ville principale si disponible ;
- nombre de villes associées si disponible ;
- ressources principales si disponible ;
- bouton “Voir les villes” ;
- bouton “Centrer sur la carte” si possible.

Si le concept de territoire n’est pas encore assez structuré côté données :
- ne pas inventer de nouvelle table ;
- utiliser les données déjà disponibles ;
- afficher une version simple :
  - territoire/zone ;
  - villes liées si détectables ;
  - sinon afficher “Données territoriales partielles”.

Ne pas bloquer le bloc sur l’absence d’un modèle parfait de territoire.

ONGLET VILLES

Objectif :
Vue micro.

Afficher une liste propre des villes/colonies du joueur.

Chaque entrée doit afficher :
- nom de la ville ;
- coordonnées ou position ;
- production active si disponible ;
- niveau de caserne si disponible ;
- statut rapide ;
- bouton “Gérer” ;
- bouton “Centrer”.

Quand le joueur clique “Gérer” :
- ouvrir le détail de cette ville précise ;
- ne pas afficher toutes les villes mélangées ;
- passer le cityId au panneau de ville si nécessaire.

Quand une ville est sélectionnée, afficher une gestion claire avec sous-onglets ou sections :

[ Vue d’ensemble ] [ Construction ] [ Recrutement ] [ Récolte / Inventaire ]

Vue d’ensemble :
- nom de ville ;
- coordonnées ;
- bâtiments construits ;
- niveaux de bâtiments si disponibles ;
- production active ;
- inventaire résumé ;
- boutons rapides :
  - Construction
  - Recrutement
  - Récolte / Inventaire
  - Centrer sur carte

Construction :
- réutiliser ConstructionPanel existant ;
- ne pas casser la logique barracks N1→N4.

Recrutement :
- réutiliser RecruitmentPanel existant ;
- doit ouvrir directement sur la ville sélectionnée ;
- conserver bouton Recruter, coûts, durée, verrous caserne.

Récolte / Inventaire :
- réutiliser les panneaux existants si disponibles ;
- ne pas créer de nouveau système économique.

ACCÈS DIRECT DEPUIS LA CARTE

Objectif :
Quand un joueur clique sur une ville/colonie sur la carte, il doit voir une action claire :

“Gérer la ville”

Comportement souhaité :

1. Le joueur clique une ville sur la carte.
2. Une petite fenêtre/panneau de contexte apparaît ou le panneau existant de tuile affiche :
   - nom de la ville ;
   - propriétaire/faction ;
   - caserne niveau X si disponible ;
   - production active si disponible ;
   - bouton “Gérer la ville”.
3. En cliquant “Gérer la ville” :
   - ouvrir CityManagementPanel ;
   - sélectionner automatiquement cette ville ;
   - afficher le détail de cette ville ;
   - ne pas ouvrir une liste générale confuse.

Si le système de clic carte existe déjà :
- brancher l’action sur le flux existant.
- ne pas créer un nouveau système de sélection parallèle.

Si le bouton est plus simple à ajouter dans TileInfoPanel :
- l’ajouter là.
- documenter que l’accès direct passe par TileInfoPanel.

Si le bouton est plus simple à ajouter dans popup de ville :
- utiliser cette voie.
- documenter.

COMPORTEMENT ERGONOMIQUE ATTENDU

Le joueur doit pouvoir faire ces parcours :

PARCOURS A — Depuis menu administratif

1. Ouvrir Gestion administrative.
2. Cliquer onglet “Villes”.
3. Voir seulement les villes.
4. Cliquer “Gérer” sur une ville.
5. Voir les sections :
   - Vue d’ensemble
   - Construction
   - Recrutement
   - Récolte / Inventaire.

PARCOURS B — Depuis la carte

1. Cliquer une ville sur la carte.
2. Voir bouton “Gérer la ville”.
3. Cliquer.
4. Ouvrir directement la gestion de cette ville.

PARCOURS C — Recrutement depuis ville

1. Ouvrir ville.
2. Cliquer sous-onglet “Recrutement”.
3. Voir les unités de cette ville seulement.
4. Voir coûts, durée, bouton Recruter.
5. Verrous caserne conservés.

PARCOURS D — Construction depuis ville

1. Ouvrir ville.
2. Cliquer sous-onglet “Construction”.
3. Construire/améliorer Caserne.
4. Après hydratation, la ville conserve buildingLevels.
