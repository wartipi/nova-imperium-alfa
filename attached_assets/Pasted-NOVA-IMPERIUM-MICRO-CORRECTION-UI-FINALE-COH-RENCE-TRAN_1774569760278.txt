POINT 1 — TEXTE FAUX DANS TREASURYPANEL

Dans TreasuryPanel, un texte dit encore :

“Ressources : 10 unités = 1 emplacement. Max 50 unités totales.”

Ce texte est faux par rapport au backend actuel.

Le backend applique simplement :
- capacité max = 50 unités totales transportées
- usedUnits = gold + food
- freeUnits = reste disponible

Il n’existe pas de règle serveur “10 unités = 1 emplacement”.

À faire :
- supprimer ce texte faux
- le remplacer par un texte strictement cohérent avec le backend réel

Exemple acceptable :
- “Capacité transport : 50 unités totales (or + nourriture).”
ou
- “Le transport de ressources est limité à 50 unités totales.”

IMPORTANT :
L’UI doit raconter exactement la règle backend réelle, rien de plus.

POINT 2 — LIBELLÉ TROMPEUR DANS CONSTRUCTIONPANEL

Dans ConstructionPanel, le bouton de construction affiche encore :

Mais canAffordBuilding() ne vérifie plus les matériaux.
Il ne vérifie maintenant que :
- les PA
- éventuellement l’état local simple (déjà construit / déjà en cours)

Donc ce libellé devient trompeur.

À faire :
- remplacer ce libellé par quelque chose de juste

Exemples acceptables :
- “PA insuffisants”
- “Impossible”
- “Conditions non remplies”

Le meilleur choix probable ici est :
- “PA insuffisants”
si le bouton est uniquement bloqué par canAffordBuilding() sur les PA

IMPORTANT :
Le message “transférez depuis la banque” doit rester géré uniquement après refus serveur INSUFFICIENT_CITY_INVENTORY, comme c’est déjà le cas.
Ne pas réintroduire de logique locale trompeuse sur les matériaux.
