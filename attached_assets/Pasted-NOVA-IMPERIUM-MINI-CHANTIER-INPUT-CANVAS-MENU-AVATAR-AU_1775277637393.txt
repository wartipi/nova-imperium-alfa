ÉTAPE 2 — MENU AVATAR AU CLIC DROIT
Dans handleCanvasContextMenu() :
- détecter d’abord si le clic droit touche l’avatar via gameEngineRef.current.isClickOnAvatar(...)

- sinon :
  - conserver le comportement actuel du menu contextuel de case

ÉTAPE 3 — SUPPRIMER L’OUVERTURE AU CLIC GAUCHE

IMPORTANT

- fermeture du tileContextMenu

ÉTAPE 4 — DOUBLE CLIC GAUCHE = DEMANDE DE DÉPLACEMENT AVATAR
Réutiliser useDoubleClick dans GameCanvas.tsx.

Comportement voulu :
- single clic gauche :
  - garde le comportement normal existant de sélection de case
  - ne lance pas le menu avatar
- double clic gauche sur une case :
  - si terrain walkable
  - si case accessible (explorée ou admin)
  - si différente de la case actuelle de l’avatar
  - alors lancer setPendingMovement({ x: hex.x, y: hex.y })

IMPORTANT
Le double clic ne doit PAS créer un nouveau flux de déplacement.
Il doit réutiliser exactement :
- pendingMovement
- MovementConfirmationModal
- handleMovementConfirm()

ÉTAPE 5 — GARDES À CONSERVER
Le double clic gauche ne doit pas lancer un déplacement si :
- l’action serveur est déjà active
- la case est non découverte (hors admin)
- la case est non walkable
- la case cible = case actuelle de l’avatar

Si possible, réutiliser au maximum les mêmes gardes que le menu contextuel “Se déplacer ici”.
