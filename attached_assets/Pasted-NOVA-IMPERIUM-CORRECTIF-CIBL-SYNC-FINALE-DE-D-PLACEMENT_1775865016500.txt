OBJECTIF
Corriger un bug de fin de déplacement :
à la fin d’un move, le joueur reste parfois affiché sur l’avant-dernière case côté client.
Un refresh manuel corrige alors la position.
Le but est de corriger la sync finale authoritative, pas de bricoler un refresh cosmétique.

1. DIAGNOSTIC
2. FICHIERS CONCERNÉS

DIAGNOSTIC À RESPECTER
Le problème suspecté n’est pas seulement “un refresh manquant”.
Le problème probable est une race condition entre :
- le timer de fin côté client dans GameCanvas
- la complétion lazy côté serveur via GET /api/player/actions/current
- la lecture de fetchPlayerPosition()
- le verrou finalSyncedRef

Constat attendu à vérifier dans le code réel :
A. La complétion authoritative du move est déclenchée côté serveur via getActiveAction()/completeAction()
B. GameCanvas fait une sync finale par timer client
C. doFinalSync() lit fetchPlayerPosition() trop tôt dans certains cas
D. finalSyncedRef peut être marqué à true avant que la vraie position finale serveur soit disponible
E. Le client reste alors visuellement sur la case précédente jusqu’au reload

OBJECTIF FONCTIONNEL EXACT
À la fin d’un déplacement :
- le client doit toujours finir sur la vraie case finale serveur
- sans nécessité de refresh manuel
- sans déplacement visuel incohérent
- sans double application de step
- sans refactor massif du système d’actions

ÉTAPE 3 — CORRECTIF MINIMAL DANS GameCanvas
Modifier doFinalSync() pour qu’il devienne authoritative-first.

COMPORTEMENT CIBLE :
1. doFinalSync() appelle d’abord fetchCurrentAction()

   - appliquer moveAvatarToHex(...)
   - seulement ensuite mettre finalSyncedRef à true

IMPORTANT
