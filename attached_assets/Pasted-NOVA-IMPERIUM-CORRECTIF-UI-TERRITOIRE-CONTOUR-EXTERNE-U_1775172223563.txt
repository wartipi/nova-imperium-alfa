OBJECTIF
Corriger le rendu visuel des territoires claimés pour que :
- l’intérieur des groupes de cases adjacentes ne soit plus surligné
- seules les bordures externes du territoire soient visibles
- les lignes internes entre cases du même owner disparaissent

SYMPTÔME ACTUEL
Dans le rendu actuel des claims, chaque case claimée est dessinée individuellement avec :
- un fill
- un contour propre

Résultat :
- si plusieurs cases claimées se touchent, les bordures internes restent visibles
- le territoire ressemble à un assemblage de cases indépendantes au lieu d’un contour de frontière

COMPORTEMENT ATTENDU
Pour un territoire formé de plusieurs cases adjacentes appartenant au même owner :
- ne pas afficher les frontières internes
- afficher uniquement les côtés exposés vers :
  - une case non claimée
  - une case claimée par un owner différent
  - l’extérieur de la carte si applicable

Exemples attendus :
1. une seule case claimée
- les 6 côtés sont visibles

2. deux cases adjacentes du même owner
- le segment partagé entre les deux disparaît
- seul le contour externe reste visible

3. un bloc de plusieurs cases connectées
- seul le périmètre extérieur est dessiné

4. deux territoires voisins mais ownership différent
- la frontière entre eux reste visible

ÉTAT RÉEL DU CODE À PRENDRE EN COMPTE
Dans GameEngine.ts, dans drawHex(...), le rendu des claims fait actuellement :
- un fill par case claimée
- un stroke par case claimée
- puis appelle drawTerritoryBorders(...)

Mais drawTerritoryBorders(...) est actuellement neutralisé par un return immédiat.

De plus, drawTerritoryBorders(...) utilise une logique incorrecte :
- il appelle UnifiedTerritorySystem.isTerritoryClaimed(neighborX, neighborY)
- cette méthode retourne un booléen
- ensuite le code traite le résultat comme un objet territoire
- cette logique doit être corrigée

OWNERSHIP CANONIQUE À UTILISER
Ne pas baser la comparaison sur factionId legacy.
La notion de “même owner” doit être calculée avec les champs canoniques du territoire :

Cas 1 — owner personnel :
- ownerType === 'player'
- même owner si ownerPlayerId identique

Cas 2 — owner faction :
- ownerType === 'faction'
- même owner si ownerFactionId identique

Sinon :
- owner différent

ÉTAPE 2 — MODIFICATION MINIMALE
Dans GameEngine.ts uniquement, applique le correctif suivant :

A. Dans le bloc de drawHex(...) qui traite territoryInfo :
- supprimer le rendu de fill interne des cases claimées
- supprimer le contour individuel autour de chaque case claimée
- conserver seulement :
  - le rendu de la colonie si colonyId existe
  - le rendu des bordures externes via drawTerritoryBorders(...)

B. Réactiver drawTerritoryBorders(...)
- retirer le return immédiat
- corriger la logique pour récupérer le territoire voisin avec :
  - UnifiedTerritorySystem.getTerritory(neighborX, neighborY)
et non :
  - UnifiedTerritorySystem.isTerritoryClaimed(...)

C. Comparaison “même owner”
Implémente une logique claire :
- si pas de territoire voisin → ce côté est une bordure
- si territoire voisin avec owner différent → ce côté est une bordure
- si territoire voisin avec même owner → ne pas dessiner ce côté

D. Couleur de bordure
Conserver une logique simple et stable :
- ownership player → bordure bleutée
- ownership faction → bordure verdâtre
Tu peux réutiliser les couleurs déjà présentes si elles sont cohérentes.

E. Largeur de ligne
Utiliser un contour lisible mais non excessif.
Objectif :
- frontière visible
- sans bruit
- sans redessiner chaque case entière

F. Ne pas ajouter d’overlay de remplissage interne
Le résultat voulu est vraiment :
- contour externe visible
- pas de masse colorée interne répétée par case
