Prompt pour l’IA — Audit de migration du vieux mode MJ client vers un vrai système admin serveur
Nouveau bloc de travail : audit de migration du vieux "mode maître de jeux" client vers un vrai système admin serveur.

Contexte du projet

Nova Imperium utilise maintenant une architecture de plus en plus serveur-autoritaires pour les mécaniques importantes.

Des blocs récents ont déjà été stabilisés :

- le spawn prototype est sécurisé
- le moteur d’actions persistantes fonctionne côté serveur
- le rôle "gm" a été supprimé du backend
- le backend fonctionne maintenant avec seulement :
  - admin
  - player
- les bypass serveur de test commencent à être centralisés côté admin
- le déplacement admin instantané fonctionne avec resynchronisation depuis la position réelle du serveur
- la section "Action en cours" dans le HUD est maintenant cohérente avec le backend

Problème actuel

Il existe encore un ancien "mode maître de jeux" côté client, hérité d’un ancien mode debug local.

Ce mode client semble encore contrôler plusieurs comportements sans passer proprement par le serveur, notamment :

- révélation complète de la carte
- visibilité immédiate des ressources
- anciens bypass locaux
- bouton "XP gratuit"
- potentiellement d’autres shortcuts client non alignés avec la source de vérité serveur

Ce système est maintenant incohérent avec la direction actuelle du projet.

Objectif de cet audit

Identifier précisément :

1. où le vieux mode MJ client est encore stocké
2. quels composants ou systèmes l’utilisent encore
3. quels comportements exacts il modifie
4. ce qui doit être migré vers des privilèges admin serveur
5. ce qui doit être supprimé du client
6. comment remplacer proprement le bouton XP gratuit par un bypass admin sur les compétences

Important :
on ne veut pas bricoler ce vieux mode client.
On veut préparer sa migration vers un vrai système admin cohérent.

Direction visée

À terme, le système doit fonctionner avec :

- un rôle serveur : admin ou player
- puis plus tard un vrai mode admin ON/OFF propre si nécessaire
- des helpers serveur explicites du type :

shouldIgnoreActionTimers(context)
shouldIgnoreActionPointCosts(context)
shouldIgnoreCompetencePointCosts(context)
shouldRevealEntireMap(context)
shouldRevealAllResources(context)

Tous basés à terme sur :
- context.role === 'admin'
- et plus tard éventuellement un flag adminModeEnabled

Mais ce bloc est uniquement un audit.
Tu ne modifies rien avant validation.

Règles de travail

Avant toute modification :

1. analyser le code existant
2. identifier tout ce que le vieux mode MJ client contrôle encore
3. distinguer :
   - ce qui est purement visuel
   - ce qui influence réellement le gameplay
   - ce qui devrait migrer côté serveur
   - ce qui devrait simplement être supprimé
4. proposer un plan de migration minimal et cohérent
5. attendre validation

Tu ne modifies rien avant validation.

Exigence de rigueur

- pas de formulation vague
- pas de supposition
- citer les fichiers et fonctions exacts
- distinguer clairement :
  - faits observés
  - comportements actuels
  - direction recommandée
  - limites de l’audit
