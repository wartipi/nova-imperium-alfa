ÉTAPE 2 — RÈGLES DE CONVERSION DES COÛTS

Appliquer ces règles :

1. Monnaie

* goldCost → fractenCost
* cost.gold → cost.fracten
* city_inventory.gold ne doit plus être la source principale pour payer une construction V2
* player_bank.gold ne doit plus être la source principale pour payer un recrutement V2

2. Métaux

* ironCost + copperCost → commonMetalsCost
* cost.iron + cost.copper → cost.common_metals
* city_inventory.common_metals devient la source principale
* player_bank.common_metals devient la source principale

3. Cuir/fourrure

* furCost → leatherFurCost
* cost.fur → cost.leather_fur
* city_inventory.leather_fur devient la source principale
* player_bank.leather_fur devient la source principale

4. Fallback legacy
   Si des données anciennes existent :

* V2 doit être prioritaire
* V1 peut être fallback seulement si V2 est absent ou 0
* ne jamais additionner V1 + V2 pour payer le même coût

ÉTAPE 3 — BACKEND CONSTRUCTION

Dans routes/cities.ts ou le fichier serveur concerné :

* remplacer les checks de coûts V1 par des checks V2
* remplacer les débits V1 par des débits V2
* conserver les colonnes V1 seulement comme fallback temporaire si nécessaire
* ne pas supprimer les anciens champs

Exemple logique attendue :

* coût fracten payé depuis city_inventory.fracten
* coût common_metals payé depuis city_inventory.common_metals
* coût leather_fur payé depuis city_inventory.leather_fur

Si fallback nécessaire :

* utiliser gold seulement si fracten insuffisant ou absent ET documenter
* utiliser iron/copper seulement si common_metals absent ET documenter
* utiliser fur seulement si leather_fur absent ET documenter

ÉTAPE 4 — BACKEND RECRUTEMENT

Auditer RecruitmentPanel et le serveur associé au recrutement.

Si le recrutement paie depuis player_bank :

* fracten doit remplacer gold
* common_metals doit remplacer iron/copper
* leather_fur doit remplacer fur

Si le recrutement est seulement client-side pour l’instant :

* convertir les types et labels
* ne pas inventer une route serveur
