IMPLÉMENTATION ATTENDUE

A. HYDRATATION / SUIVI ACTION EN COURS
Dans GameCanvas.tsx :
- au montage, fetchCurrentAction()
- si action active :
  - la stocker dans usePlayerActions
- pendant qu’une action est active :
  - polling régulier de /api/player/actions/current
  - fréquence recommandée : 250 ms à 500 ms
- à la fin :
  - setActiveAction(null)
  - fetchPlayerPosition()
  - resynchroniser l’avatar depuis la source serveur

B. TIMER VISIBLE
Ajouter un affichage visible en jeu pendant un move actif :
- type d’action
- destination
- temps restant
- coût total
- éventuellement bouton annuler si déjà disponible proprement

Le widget doit être simple, lisible, non invasif.

C. DÉPLACEMENT VISUEL CASE PAR CASE
Utiliser activeAction.path pour calculer la position visuelle courante.

Règle de progression voulue :
- le joueur doit être présent sur chaque tuile une à la fois
- durée d’une étape = step.cost × 5 secondes
- la progression se base sur :
  - action.startTime
  - action.expectedEndTime
  - action.path
  - step.cost

Méthode recommandée :
1. calculer elapsedMs = now - startTime
2. parcourir path[1..] avec coût cumulé
3. convertir chaque coût en durée :
   stepDurationMs = step.cost * 5000
4. déterminer dans quelle étape temporelle on se trouve
5. déplacer l’avatar local vers cette tuile avec moveAvatarToHex(...)

IMPORTANT
- pas d’interpolation libre entre deux tuiles
- pas de glissement continu
- présence case par case uniquement
- une tuile à la fois

D. FIN D’ACTION
