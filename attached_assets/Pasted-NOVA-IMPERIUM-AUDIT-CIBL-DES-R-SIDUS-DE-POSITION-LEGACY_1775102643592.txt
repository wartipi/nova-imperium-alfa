CONTEXTE VALIDÉ
Le flux principal claim → synchro UI → fondation de colonie a été corrigé.
Le bug principal venait de l’utilisation d’une mauvaise source de position pour le claim.
Le claim utilise maintenant `usePlayer.getState().avatarHexPosition`.

Mais il reste probablement des résidus legacy ailleurs dans le client.

OBJECTIF
Trouver précisément tous les endroits où :
1. une feature utilise encore `gameEngine.getAvatarPosition()` comme source canonique
2. une feature utilise encore des helpers territory legacy au lieu de l’ownership canonique
3. une incohérence locale/monde pourrait encore exister en silence

PÉRIMÈTRE D’AUDIT
Tu dois auditer explicitement :

A. Position joueur / coordonnées
- tous les usages de `gameEngine.getAvatarPosition()`
- tous les usages de `avatarHexPosition`
- tous les usages de `originWorldX` / `originWorldY`
- tous les endroits où on construit `worldX/worldY` depuis une position locale
- tous les endroits où on lit une position joueur pour une action métier

B. Territoires / ownership
- tous les usages de `UnifiedTerritorySystem.getAccessibleTerritories(...)`
- tous les usages de `getPlayerTerritories(...)`
- tous les usages de `getFactionTerritories(...)`
- tous les usages des champs legacy :
  - `playerId`
  - `playerName`
  - `factionId`
  - `factionName`
- vérifier si une UI importante filtre encore sur ces champs legacy au lieu de :
  - `ownerType`
  - `ownerPlayerId`
  - `ownerFactionId`

C. Flux sensibles à contrôler
- claim territoire
- fondation de colonie
- cartographie
- déplacement

- tout panneau UI qui dépend de l’ownership
