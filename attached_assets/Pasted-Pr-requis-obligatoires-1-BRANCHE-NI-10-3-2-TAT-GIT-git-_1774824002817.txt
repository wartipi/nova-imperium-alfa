5. RISQUES RÉSIDUELS
1. Délai de détection fin de trajet : max 1500ms + 300ms buffer
Si le endTimer fire à msToEnd + 300 et que ce poll échoue (réseau), la détection de fin attend le prochain setInterval (1500ms). Total max : 300 + 1500 = 1800ms après expectedEndTime. Comportement correct — la sync finale finira par se déclencher. Impact : léger délai visuel en fin d'action.

2. Concurrence endTimer + pollInterval
Si l'endTimer et le pollInterval déclenchent simultanément pollServer, les deux tentent la sync finale. Protégé par finalSynced = true dans le premier qui aboutit. Idempotent.

3. clearTravelVisualHexPosition sans setTravelVisualHexPosition dans les deps
setTravelVisualHexPosition a été retiré des dépendances (plus utilisé). clearTravelVisualHexPosition reste. Correct. ESLint exhaustive-deps pourrait signaler un warning sur d'autres états lus dans pollServer (useMap.getState() via closure), mais useMap.getState() est une lecture directe du store Zustand sans abonnement React — pas de re-render, pas d'effet de bord.

4. Race condition résiduelle finalSynced
Si le composant se démonte juste après finalSynced = true mais avant fetchPlayerPosition().then(...), la promesse continue en tâche de fond et appelle moveAvatarToHex sur un composant démonté. Impact : nul sur la DB (déjà correcte), potentiel warning React stale store. Pré-existant depuis Phase 3, non résolu par périmètre.
