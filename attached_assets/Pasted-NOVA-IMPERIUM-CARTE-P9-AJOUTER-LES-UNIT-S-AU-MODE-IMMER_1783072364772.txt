NOVA IMPERIUM — CARTE — P9 / AJOUTER LES UNITÉS AU MODE IMMERSIVE
Branche : NI-10.09

OBJECTIF
Ajouter l’affichage des unités au mode immersive Pixel HD, en utilisant uniquement les données déjà disponibles côté client.

Ce bloc ne doit pas ajouter encore :

* routes
* rivières
* avatar
* autres joueurs / présence multijoueur avancée
* animation de déplacement
* nouvelle logique de combat
* nouvelle logique de sélection

Ces couches restent pour les blocs suivants.

OBJECTIF P9
Afficher en mode immersive :

1. Les unités déjà chargées côté client.
2. Sur leurs coordonnées existantes.
3. Avec un marqueur visuel simple, lisible et compatible Pixel HD.
4. Sans modifier la logique d’unités.
5. Sans modifier les règles de mouvement, combat, sélection ou visibilité.

IMPORTANT
Ce bloc est visuel seulement.
Il doit seulement lire les données existantes.
Il ne doit pas changer la logique des unités.

ÉTAPE 1 — AUDIT DES DONNÉES UNITÉS DISPONIBLES

Inspecter :

* GameCanvas.tsx
* stores déjà utilisés par GameCanvas
* types d’unités client
* GameEngine.ts seulement pour comprendre comment la vue stratégique dessine les unités
* tout hook déjà chargé côté client pour les unités

Identifier précisément :

* où sont les unités côté client
* leur structure exacte :

  * id
  * type
  * name
  * x
  * y
  * ownerId / playerId / factionId si disponible
  * health / maxHealth si disponible
  * movement / maxMovement si disponible
  * selected si disponible
* comment la vue stratégique les affiche actuellement
* comment la sélection / clic unité est déjà gérée

Important :

* ne pas faire de nouveau fetch
* ne pas créer de nouveau store
* ne pas modifier backend
* ne pas inventer de champs

ÉTAPE 2 — TYPES

Ajouter dans PixelMapRenderer.ts des types locaux souples.

Exemple autorisé :

export interface PixelMapUnit {
id: string | number;
type?: string | null;
name?: string | null;
x: number;
y: number;
ownerId?: string | number | null;
playerId?: string | number | null;
factionId?: string | number | null;
health?: number | null;
maxHealth?: number | null;
movement?: number | null;
maxMovement?: number | null;
selected?: boolean;
}

Étendre PixelMapRenderOptions :

units?: PixelMapUnit[];
showUnits?: boolean;
selectedUnitId?: string | number | null;

Valeur par défaut :

* showUnits true

Ne pas exporter plus que nécessaire.
Si PixelMapUnit doit être exporté pour GameCanvas.tsx, l’exporter.
Sinon, garder local si possible.

ÉTAPE 3 — RENDU DES UNITÉS

Ajouter une fonction interne :

drawUnitsLayer(...)

Rendu recommandé :

* marqueur petit mais lisible
* style pixel / médiéval
* pas d’emoji
* pas d’image externe
* forme simple :

  * rond / bouclier / pion
  * contour sombre
  * couleur propriétaire si owner disponible
  * symbole interne selon type si possible

Exemples visuels simples :

* worker / settler / civilian : petit losange clair
* soldier / military : petit bouclier
* scout : petit triangle
* default : pion rond

Si type inconnu :

* fallback pion rond

ÉTAPE 4 — POSITIONNEMENT

Convertir x/y unité vers centre hex avec la même géométrie que les tuiles.

Règles :

* x/y unité doivent correspondre aux coordonnées de tuile
* dessiner au centre de l’hex
* si plusieurs unités sur la même case :

  * ne pas crash
  * léger offset déterministe par index
  * ou empilement simple avec compteur discret si déjà facile
* ne pas modifier la logique de stacking

ÉTAPE 5 — VISIBILITÉ / FOG

Règles strictes :

* ne pas afficher une unité sur une tuile non visible
* fog total masque les unités
* fog ring peut assombrir mais ne doit pas cacher une unité visible si la logique actuelle la montre
* ne jamais révéler une unité cachée par l’exploration
* ne pas recalculer la vision

Le renderer doit seulement consommer :

* isHexVisible
* données unités déjà chargées
* callbacks existants si disponibles

Si la logique exacte de visibilité des unités est gérée ailleurs :

* transmettre un callback depuis GameCanvas.tsx, par exemple :

shouldShowUnit?: (unit: PixelMapUnit) => boolean

Ce callback doit réutiliser la logique existante.
Ne pas inventer une logique parallèle.

ÉTAPE 6 — SÉLECTION DES UNITÉS

Si selectedUnitId ou unité selected est déjà disponible :

* dessiner un contour de sélection autour de l’unité
* ne pas modifier la logique de sélection
* ne pas changer les handlers de clic

Si la sélection unité n’est pas disponible facilement :

* ne pas forcer
* documenter comme limite restante
