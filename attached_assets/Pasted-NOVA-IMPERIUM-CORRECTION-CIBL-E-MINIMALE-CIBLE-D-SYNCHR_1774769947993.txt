CONTEXTE VALIDÉ
L’audit a identifié la cause racine :

- GameCanvas.tsx déplace maintenant l’avatar local case par case pendant un move actif
- ce déplacement visuel passe par moveAvatarToHex(...)
- mais moveAvatarToHex(...) dans usePlayer.tsx appelle encore savePlayerPosition(...)
- donc la DB player_positions est réécrite pendant toute l’action avec des positions intermédiaires
- au reload / remount / hydratation, la position lue depuis la DB peut déjà être celle de destination
- résultat visible : le joueur “snap” immédiatement, puis le timer continue

DÉCISION VALIDÉE
Le correctif minimal à faire maintenant est UNIQUEMENT :
- empêcher savePlayerPosition(...) pendant qu’une action de déplacement est active
