PROBLÈME RÉEL À TRAITER MAINTENANT
Le preview client doit respecter les mêmes règles métier que le serveur.

ÉTAT MÉTIER SERVEUR DÉJÀ EN PLACE
Dans `server/routes/playerActions.ts`, la route move :
- refuse une destination non découverte
- refuse un chemin qui traverse une case non découverte
- utilise `player_discovered_tiles` comme vérité serveur

PROBLÈME CÔTÉ CLIENT
Le preview client ne doit pas afficher un trajet valide si :
- la destination n’est pas découverte
- une étape du chemin traverse une case non découverte

OBJECTIF
Faire en sorte que le preview client respecte déjà la même règle que le serveur :

AUTORISÉ :
- chemin entièrement sur cases découvertes

INTERDIT :
- destination non découverte
- chemin qui traverse une case non découverte

IMPORTANT
Le but n’est PAS de refaire le serveur.
Le but est d’aligner le preview client sur la règle serveur déjà validée.

CIBLE TECHNIQUE ATTENDUE
Le preview client doit utiliser la règle suivante :

Une destination est previewable si :
- `isHexExplored(targetX, targetY)` est vrai

Un chemin est previewable si :
- chaque case du path calculé (hors départ) est découverte

SOLUTION ATTENDUE
Tu choisis la plus petite solution propre entre :

OPTION A — préférée si minimale
Dans `MovementSystem.previewMovement()` :
- calculer le path via `HexPathfinding.findPath(...)`
- puis filtrer / invalider le résultat si :
  - destination non découverte
  - ou une étape du path n’est pas découverte
- renvoyer alors :
  - `success: false`
  - `path: []`
  - `totalCost: 0`

OPTION B — acceptable si plus propre
Ajouter un contrôle optionnel dans `HexPathfinding.findPath(...)`
pour ignorer les cases non découvertes,
à condition que cela reste petit, lisible, et ne casse pas les autres usages.

PRÉFÉRENCE
Je préfère la plus petite correction lisible.
Ne complexifie pas `HexPathfinding.ts` inutilement si `MovementSystem.previewMovement()` suffit.
