- ou garder seulement une indication visuelle “PA indicatifs” ;
- corriger le title du bouton pour ne pas dire “Points d’action insuffisants” si le bouton n’est pas réellement bloqué.

Ne pas ajouter de débit PA serveur dans ce bloc.
Ne pas ajouter de nouvelle colonne.
Ne pas ajouter de route PA.

Vérifier :

- apiStartRecruitment est bien appelé.

2. Corriger l’incohérence points d’action

Dans RecruitmentPanel.tsx :

- Si canAffordUnit() ne bloque plus le bouton :
  - retirer le title “Points d’action insuffisants” ;
  - ne pas laisser croire que les PA bloquent le recrutement.
- Option acceptable :
  - afficher les PA comme information seulement.
- Option acceptable :
  - laisser getUnitRecruitmentCost() affiché, mais préciser que la validation réelle est serveur/city_inventory.
- Ne pas réintroduire un blocage PA côté client comme source de vérité sans validation serveur.

3. Ajouter une mention UX sur les coûts

Ajouter une petite note dans le panneau recrutement, par exemple sous le titre :

“Note : les coûts affichés sont indicatifs pendant la migration. Le serveur valide et débite l’inventaire réel de la ville.”

Contraintes :
- texte court ;
- pas de gros redesign ;
- pas de nouveau composant complexe.

4. Améliorer le message ressources insuffisantes si simple

ou équivalent.

5. Vérifier le commentaire serveur

Confirmer que le commentaire au-dessus de start-recruitment est cohérent :
- doit mentionner transaction atomique ;

Ne modifier que le commentaire si nécessaire.
