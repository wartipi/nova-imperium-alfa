CONTEXTE VALIDÉ

V3-D5-C2 :
- POST /api/cities/:cityId/start-recruitment est atomique.
- startRecruitmentTransaction() fait dans une transaction DB :
  1. vérification production active ;
  2. vérification city_inventory ;
  3. débit conditionnel city_inventory ;
  4. insertion/upsert city_production.
- Aucun risque de perte entre débit et city_production.

V3-D5-D :
- client/src/lib/api/citiesApi.ts expose :
  apiStartRecruitment(cityId: number, unitType: string)
- La fonction conserve les erreurs serveur dans error.body :
  - PRODUCTION_ALREADY_ACTIVE
  - INSUFFICIENT_CITY_INVENTORY + missing[]
  - autres erreurs lisibles.
- L’UI n’est pas encore branchée.

OBJECTIF DE CE BLOC

Modifier uniquement le flux de démarrage du recrutement dans RecruitmentPanel.tsx pour utiliser :

apiStartRecruitment(cityId, unitType)

Le recrutement doit devenir serveur-authoritative pour :
- validation des ressources ;
- débit city_inventory ;
- refus si production active ;
- création city_production.

C. Erreur inconnue

Respecter le pattern UI existant :
- toast si déjà utilisé ;
- state error si déjà utilisé ;
- console.error si nécessaire.
