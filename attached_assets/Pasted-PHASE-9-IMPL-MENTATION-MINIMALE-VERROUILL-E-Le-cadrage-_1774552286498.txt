PHASE 9 — IMPLÉMENTATION MINIMALE VERROUILLÉE

Le cadrage Phase 9 est maintenant validé.
Tu peux commencer l’implémentation, mais uniquement selon le chemin minimal déjà verrouillé.

RÈGLES ABSOLUES
- aucun refactor massif
- aucun changement d’architecture
- aucune nouvelle mécanique hors périmètre
- aucune ressource supplémentaire au-delà de gold + food
- ne pas globaliser production_per_turn
- ne pas ajouter de colonnes économiques dans factions
- ne pas garder un calcul économique client en parallèle du calcul serveur
- pas de WebSocket
- pas de cron
- pas de tick temps réel automatique

OBJECTIF
Implémenter une économie globale minimale de faction, cohérente avec l’existant.

PÉRIMÈTRE VERROUILLÉ
1. Nouvelle table `faction_economy`
   - `faction_id`
   - `gold`
   - `food`
   - `last_processed_turn`
   - `updated_at`

2. Extension de `cities`
   - ajouter `gold_per_turn`

3. Calcul ville
   - étendre `BUILDING_YIELDS`
   - intégrer `gold_per_turn` dans `recalculateCityEconomy()`
   - en v1, `gold_per_turn` dépend uniquement des bâtiments
   - ne pas dépendre de la population

4. Service d’agrégation
   - `aggregateFactionIncome(factionId)`
   - somme `food_per_turn` + `gold_per_turn` sur les villes de la faction

5. Tick économique
   - `POST /api/economy/tick`
   - reçoit `currentTurn` dans le body
   - garde d’idempotence via `last_processed_turn`
   - applique revenus et dépenses
   - met à jour `faction_economy`

6. Lecture API
   - `GET /api/economy/me`
   - retourne les stocks + revenus agrégés utiles à l’affichage

7. Client
   - `TreasuryPanel` devient lecture pure depuis l’API
   - supprimer l’accumulateur économique local pertinent dans `useNovaImperium.processTurn()`
   - ne plus calculer les revenus localement dans le panneau

ORDRE D’IMPLÉMENTATION OBLIGATOIRE

Relis uniquement les fichiers nécessaires et annonce :
- fichiers à modifier
- impact attendu
- invariants à préserver

- table `faction_economy`
- colonne `gold_per_turn` dans `cities`
- valeurs par défaut cohérentes
- initialisation minimale pour les factions existantes si nécessaire

Puis donne :
- fichiers modifiés
- schéma exact
- ce qui a été ajouté

Puis arrête-toi.

ÉTAPE 3 — Calcul économique ville

- extension `BUILDING_YIELDS`
- `recalculateCityEconomy()` avec `gold_per_turn`
- extension du DTO ville si nécessaire

Puis donne :

- déclencheurs conservés

Puis arrête-toi.

ÉTAPE 4 — Service économie faction

- Incertain
- Échec
