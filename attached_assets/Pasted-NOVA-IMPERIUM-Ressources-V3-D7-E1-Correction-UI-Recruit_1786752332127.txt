Correction UI RecruitmentPanel : bouton Recruter + durée + coût visible

RÔLE
Tu es l’agent technique sur le repo Nova Imperium.
Objectif : corriger le panneau de recrutement afin qu’un joueur voie clairement comment recruter une unité, combien elle coûte, et combien de tours elle prend à produire.

Ce bloc doit corriger uniquement cette lisibilité/action UI.

OBJECTIF 1 — Bouton de recrutement visible

Dans RecruitmentPanel.tsx :

Chaque carte/ligne d’unité doit afficher un bouton d’action clair :

- si unité disponible :
  bouton texte : “Recruter”
- si unité verrouillée par caserne :
  bouton désactivé : “Caserne Nv.X requise”
- si ressources insuffisantes :
  bouton désactivé : “Ressources insuffisantes”
- si production déjà active :
  bouton désactivé : “Production en cours”
- si action en cours :
  bouton désactivé : “Recrutement…”

Le bouton doit être visible sans devoir deviner où cliquer.

Le bouton doit appeler le flux existant :
- handleRecruit(unit.id)
- apiStartRecruitment(...)
- hydrateCitiesFromServer() après succès

Ne pas créer un nouveau flux parallèle.

OBJECTIF 2 — Afficher la durée de création

Pour chaque unité, afficher clairement la durée serveur :

Format recommandé :
- “Durée : X tour”
- “Durée : X tours”

La durée doit venir de GET /recruitment-costs si disponible :

serverRecruitmentCosts[unit.id]?.duration

Si le coût serveur n’est pas encore chargé :
- afficher “Durée : chargement…”
ou utiliser le fallback existant seulement si déjà présent et fiable.

Ne pas inventer de durée différente.

OBJECTIF 3 — Afficher le coût de recrutement

Pour chaque unité, afficher clairement les ressources de recrutement :

Exemple :
- “Coût : 2 Nourriture, 1 Contrat de travail”

Utiliser les données serveur :
- serverRecruitmentCosts[unit.id]?.cost

Si coût non chargé :
- afficher “Coût : chargement…”
ou fallback existant déjà utilisé.

Ne pas afficher upkeep/entretien comme coût actif.

OBJECTIF 4 — Conserver le verrou caserne

Le bouton “Recruter” doit rester désactivé si :

- barracksLevel < requiredLevel

Et afficher :
- “Caserne Nv.X requise”

L’indicateur visuel actuel “🔒 Caserne Nv.X requise” peut rester, mais le bouton doit aussi expliquer le blocage.

OBJECTIF 5 — RecruitmentPanelZustand

Ce panneau est encore actif ou potentiellement visible via CityManagementPanel.

Vérifier s’il sert vraiment de panneau de recrutement visible.

Si oui :
- ajouter aussi un bouton visible ou au minimum un message clair indiquant que le recrutement actif se fait dans RecruitmentPanel.
- ne pas laisser un panneau d’unités sans action compréhensible.

Si ce panneau est seulement informatif :
- ajouter une mention claire :
  “Panneau informatif — utilisez le panneau Recrutement pour former des unités.”
- documenter.

Ne pas supprimer ce panneau dans ce bloc.

OBJECTIF 6 — Erreurs serveur lisibles

Si le serveur refuse :
