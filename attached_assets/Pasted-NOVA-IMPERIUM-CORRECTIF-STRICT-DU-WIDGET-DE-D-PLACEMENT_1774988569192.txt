CONTEXTE VALIDÉ
Le code actuel a déjà :
- stepStartedAt
- serverStep
- journeyRemainingMs
- isStartingPhase
- libellé "Départ en cours…"

Mais en runtime, au début d’un nouveau trajet, le widget affiche encore :
- Tuile N / N
- Arrivée imminente…
- Finalisation…

Donc le vrai problème n’est pas uniquement le libellé.
Le widget entre trop tôt dans la branche “dernier step / fin de trajet”.

OBJECTIF
Empêcher qu’au début d’une nouvelle action de déplacement,
le widget puisse se comporter comme s’il était déjà au dernier step.

COMPORTEMENT ATTENDU
Au départ d’une nouvelle action move :
- le widget doit être dans un état de début de trajet
- pas dans un état de fin de trajet
- il ne doit pas afficher :
  - Arrivée imminente…
  - Finalisation…
- il doit afficher à la place un état cohérent de départ :
  - Départ en cours…
  - et/ou les timers normaux du premier step si disponibles

IMPORTANT
Je veux corriger la logique d’entrée dans la branche UI de fin,
pas seulement remplacer un texte.

Tant qu’on est dans la phase de départ d’une nouvelle action :
- le widget ne doit PAS entrer dans la branche UI “dernier step”
