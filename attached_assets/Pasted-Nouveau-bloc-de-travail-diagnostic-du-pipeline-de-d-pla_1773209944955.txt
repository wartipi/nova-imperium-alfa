Nouveau bloc de travail : diagnostic du pipeline de déplacement et préparation de la migration du mode admin.

Contexte du projet

Nova Imperium utilise un moteur d’actions persistantes côté serveur.

Le déplacement du joueur fonctionne via la route :

POST /api/player/actions/move

Cette route doit :
1. recevoir la destination
2. calculer un path via findPath()
3. créer une action persistante via createMoveAction()
4. stocker cette action en base
5. la rendre visible via GET /api/player/actions/current

Une section "Action en cours" dans l’interface affiche ensuite l’action active.

Des modifications récentes ont été appliquées :

- suppression du rôle "gm"
- simplification du système de rôles : admin / player
- bypass timer pour admin
- correctif du timer UI dans ActiveActionWidget
- ajout d’une structure future pour bypass des coûts en points d’action

Problème observé en test réel

Lorsqu’un déplacement est tenté :

- aucune nouvelle action n’apparaît
- la section "Action en cours" reste vide
- le déplacement ne semble pas être exécuté
- aucune action persistante n’est créée

Donc le problème est probablement dans le pipeline de déplacement lui-même, et pas seulement dans l’affichage.

Objectif de cet audit

Identifier précisément où le pipeline de déplacement s’arrête :

- côté client
- côté API
- côté serveur
- ou dans la création d’action persistante

Règles de travail

Avant toute modification :

1. reproduire le problème
2. analyser le pipeline complet de déplacement
3. identifier l’endroit exact où l’exécution s’arrête
4. expliquer la cause exacte
5. proposer la correction minimale

Tu ne modifies rien avant validation.

Exigence de rigueur :

- pas de supposition
- pas de formulation vague
- uniquement des faits démontrés
- citer les fichiers et fonctions exacts
