ÉTAPE 2 — COMPATIBILITÉ GÉOMÉTRIE

Comparer la géométrie actuelle avec celle du prototype :

Prototype :

* hex flat-top
* screenX = x * hexSize * 1.5
* screenY = y * hexHeight + (x % 2) * hexHeight / 2
* zoom par hexSize
* caméra camX / camY
* screenToHex approximatif

Vérifier :

* si le GameEngine actuel utilise la même géométrie
* si la carte 150×90 et les segments 3×3 restent compatibles
* si le renderer peut consommer les tuiles existantes sans recalculer la carte
* si les coordonnées monde actuelles peuvent être conservées

ÉTAPE 5 — COMPATIBILITÉ PERFORMANCE

Auditer :

* nombre de sprites générés
* taille 56×49
* cache terrain|variant|frame
* animation eau 700 ms
* nombre de tuiles visibles par viewport
* coût du fog overlay
* coût des icônes de ressources
* impact mobile
* impact zoom élevé
* impact carte 150×90

Déterminer :

* si le renderer peut être activé sans lag
* si l’eau animée doit rester optionnelle
* si la génération de sprites doit être pré-cache
* si le cache doit être limité ou persistant

ÉTAPE 6 — STRATÉGIE D’INTÉGRATION

Proposer une stratégie sûre :

* rendre seulement les terrains au début
* ajouter ensuite fog / grille / sélection
* ajouter ensuite ressources / colonies / unités / ownership
* fallback immédiat vers renderer actuel
