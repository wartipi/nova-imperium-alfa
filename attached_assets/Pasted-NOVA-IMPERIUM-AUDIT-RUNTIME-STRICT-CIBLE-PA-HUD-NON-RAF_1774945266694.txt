PHASE A — AUDIT DU HUD PA (PANNEAU EN HAUT À DROITE)

BUT
Déterminer si le problème est :
- absence de déduction côté serveur
- absence de refresh API/store
- ou affichage stale du HUD

TESTS OBLIGATOIRES

A1. ÉTAT INITIAL
Avant déplacement :
- noter la valeur HUD PA visible
- lire la valeur via fetchPlayerState() / API équivalente
- lire si possible la valeur DB
- confirmer qu’elles sont identiques au départ

A2. JUSTE APRÈS CRÉATION DU MOVE
Créer un trajet multi-step coût > 1
Puis immédiatement :
- noter HUD PA
- appeler fetchPlayerState()
- appeler fetchCurrentAction()
- lire DB si possible

Attendu :
- pas de déduction upfront
- HUD et API doivent rester inchangés immédiatement après création

A3. APRÈS PREMIER STEP CONFIRMÉ
Au moment du premier step serveur confirmé :
- prouver si GameCanvas émet nova:ap-refresh
- prouver si MedievalHUD reçoit nova:ap-refresh
- prouver si fetchPlayerState() retourne une valeur décrémentée
- noter la valeur HUD affichée

A4. APRÈS STEP SUIVANT
Même protocole

A5. FIN DE TRAJET
- noter HUD final
- fetchPlayerState() final
- fetchCurrentAction() final
- DB si possible
- confirmer si somme débitée = totalCost

QUESTIONS À TRANCHER
1. Les PA baissent-elles réellement côté API ?
2. Les PA baissent-elles réellement en DB ?
3. Le HUD reste-t-il stale malgré une API correcte ?
4. L’event nova:ap-refresh part-il vraiment ?
5. Le listener MedievalHUD s’exécute-t-il vraiment ?
