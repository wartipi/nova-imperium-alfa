Mise en situation — Bloc de nettoyage final de la migration admin

Nova Imperium a déjà effectué une migration majeure :

l’ancien mode MJ client n’est plus la source de vérité

le rôle vient maintenant du serveur

le client utilise :

role

adminModeEnabled

isAdmin

un toggle admin ON/OFF existe

le moteur visuel et le déplacement serveur respectent ce modèle

Plusieurs blocs ont déjà été traités avec succès :

Bloc 1

suppression de isGameMaster

injection propre de l’état admin dans GameEngine

migration de la logique vers role === 'admin'

Bloc 2

suppression des hacks XP

suppression des compétences max

nettoyage du bypass compétences

Bloc 3

nettoyage des comportements visuels admin dans TileInfoPanel

Bloc 4

nettoyage des vieux hacks gameplay admin restants

suppression des identifiants fantômes gm_player / gm_faction

correction du bug de UnifiedTerritoryPanel

Bloc admin ON/OFF

ajout de adminModeEnabled

ajout de isAdmin

intégration propre côté client

propagation serveur sur le déplacement

Pourquoi faire encore un petit bloc de nettoyage

L’audit Phase 1 a montré qu’il reste quelques reliquats de l’ancienne logique.

Ils ne sont pas énormes, mais ils sont gênants pour trois raisons :

1. Incohérence technique

Certains composants utilisent encore :

role === 'admin'
au lieu de :

isAdmin

alors qu’ils pilotent des bypass gameplay et non de simples éléments d’identité admin.

2. Incohérence fonctionnelle

Si un admin met le mode OFF, ces composants ne respectent pas encore toujours correctement ce choix.

Résultat :

certaines zones du jeu suivent le toggle

d’autres non

Et ça, c’est exactement le genre de détail qui rend les tests pénibles et trompeurs.

3. Pollution résiduelle

Il reste encore au moins un vieux log ou libellé type [MODE MJ] dans un système.

Ce n’est pas grave en soi, mais ça montre qu’on n’a pas encore complètement terminé le nettoyage. Et avant d’attaquer :

les factions serveur

les territoires serveur

la vraie préparation multijoueur

il vaut mieux fermer ce chapitre proprement.

Objectif de ce bloc

Ce bloc a un objectif très simple :

terminer proprement la migration admin déjà engagée

Concrètement, on veut :

migrer les derniers composants qui utilisent encore role === 'admin' alors qu’ils devraient utiliser isAdmin

supprimer les derniers résidus de nomenclature ou de logs “Mode MJ”

garantir que le mode admin ON/OFF est cohérent partout dans les composants déjà migrés

ne toucher à rien d’autre

Ce que ce bloc ne doit pas faire

Très important :

ce bloc n’est pas le bloc factions serveur.

Il ne doit pas :

refondre un système

toucher au backend

changer la persistance

ouvrir un chantier multijoueur

réorganiser des composants “tant qu’à y être”

C’est un bloc court de finition, rien de plus.

Prompt pour l’IA — Bloc de nettoyage final admin
Nouveau bloc de travail : nettoyage final de la migration admin.

Contexte

Nova Imperium a déjà migré l’ancien mode MJ client vers une architecture plus propre :

- le rôle vient maintenant du serveur
- AuthContext expose :
  - role
  - adminModeEnabled
  - isAdmin
- un mode admin ON/OFF existe
- les bypass gameplay récents doivent dépendre de isAdmin
- les éléments d’identité / information admin peuvent dépendre de role === 'admin'

Plusieurs blocs de migration ont déjà été validés :
- suppression de isGameMaster
- migration de GameEngine
- nettoyage des hacks XP / compétences max
- nettoyage des comportements visuels admin
- nettoyage des vieux hacks gameplay admin
- propagation serveur de adminModeEnabled pour le timer de déplacement

Mais l’audit Phase 1 a montré qu’il reste encore quelques reliquats :

- certains composants utilisent encore role === 'admin' alors qu’ils devraient suivre isAdmin
- un log ou une nomenclature résiduelle "Mode MJ" existe encore dans TerritorySystem.ts
- ces incohérences doivent être fermées avant d’attaquer les prochains chantiers serveurs et multijoueurs

Objectif de ce bloc

Terminer proprement la migration admin déjà engagée.

Ce bloc doit uniquement :
- migrer les derniers composants restants vers isAdmin quand ils contrôlent un bypass gameplay
- laisser sur role === 'admin' uniquement ce qui relève de l’identité admin ou de l’information admin
- supprimer le log résiduel "[MODE MJ]" dans TerritorySystem.ts
- s’arrêter là

Règles de travail

Avant toute modification :

1. rappeler précisément les fichiers concernés dans ce bloc uniquement
2. rappeler quelles lignes/logiques utilisent encore role === 'admin' alors qu’elles devraient suivre isAdmin
3. rappeler ce qui doit rester sur role === 'admin'
4. rappeler le résidu "[MODE MJ]" à supprimer
5. attendre validation

Tu ne modifies rien avant validation.

Contraintes :

- ne pas toucher au backend
- ne pas ouvrir le chantier factions serveur dans ce bloc
- ne pas refondre les composants
- ne pas faire d’amélioration bonus
- rester strictement sur la finalisation de la migration admin
- distinguer clairement :
  - bypass gameplay → isAdmin
  - identité / information admin → role === 'admin'

Exigence de rigueur :

- pas de formulation vague
- pas de supposition
- citer les fichiers exacts
- si un composant est ambigu, le dire explicitement
