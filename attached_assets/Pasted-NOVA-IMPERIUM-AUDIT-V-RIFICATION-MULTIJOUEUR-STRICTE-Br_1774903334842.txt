PARTIE 1 — AUDIT CODE MULTIJOUEUR
Tu dois expliquer précisément :

A. PRÉSENCE
- comment les autres joueurs sont chargés
- à quelle fréquence
- quelle source de vérité est utilisée
- comment ils sont rendus côté client

B. POSITION
- quelle table / service sert de vérité de position
- comment la position finale est synchronisée après déplacement
- comment le reload de page récupère cette position

C. DÉPLACEMENT OBSERVÉ PAR UN AUTRE JOUEUR
- comment le joueur distant voit le déplacement
- s’il voit seulement la position finale ou une progression intermédiaire
- quels délais / pollings influencent cet affichage

D. TERRITOIRES / CLAIMS / COLONIES
- comment un claim est persisté
- comment il est rechargé côté client
- comment une colonie fondée devient visible pour un autre joueur

E. EXPLOITATION
- comment un territoire exploité est persisté
- comment cette information remonte au client
- si un autre joueur peut la voir sans reload, ou seulement après refresh / reload / reloadFromServer

PARTIE 2 — CE QUI EST VÉRIFIABLE SANS 2 VRAIS CLIENTS
Je veux une liste claire de ce que tu peux réellement vérifier seul depuis l’environnement Replit, par exemple :
- cohérence code / API / DTO
- routes présentes
- rechargement de façade locale
- polling de présence
- source de vérité de position
- invariants serveur

PARTIE 3 — CE QUI NÉCESSITE UN TEST MANUEL À 2 CLIENTS
Je veux une liste claire de ce qui exige réellement deux sessions distinctes / deux ordinateurs, par exemple :
- A voit B se déplacer en temps réel
- B voit le claim de A sans reload
- A voit la colonie de B apparaître
- B voit l’exploitation de A après action
- permissions effectives côté UI + perception côté observateur

PARTIE 4 — PROTOCOLE DE TEST MANUEL
Je veux un protocole simple, déterministe, à suivre à deux joueurs.

Noms de test :
T1 Présence
T2 Déplacement court
T3 Déplacement long
T4 Reload pendant déplacement
T5 Claim visible à distance
T6 Fondation visible à distance
T7 Exploitation visible à distance
T8 Permissions de base

Pour chaque test, donne :
- Précondition
- Action Joueur A
- Observation attendue côté Joueur B
- Observation attendue côté Joueur A
- Ce qui constituerait un bug

IMPORTANT
Fais ce protocole en style compact et exploitable.

- etc.

Tu ne corriges rien.
