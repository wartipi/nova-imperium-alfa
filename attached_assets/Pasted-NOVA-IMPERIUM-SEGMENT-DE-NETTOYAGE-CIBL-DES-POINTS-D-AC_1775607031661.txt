NOVA IMPERIUM — SEGMENT DE NETTOYAGE CIBLÉ DES POINTS D’ACCÈS UI
Branche : NI-10.3

RÔLE
Tu agis comme intervenant technique sous contrainte stricte.
Tu dois faire un nettoyage ciblé, minimal, sans refactor massif, sans changement d’architecture, sans toucher à la logique métier serveur valide.
Tu ne dois pas “réinventer” de nouveaux points d’accès.
Tu dois uniquement réaligner l’UI sur les chemins canoniques déjà validés.

PRIORITÉS
Simplicité > Lisibilité > Stabilité > Compatibilité

INTERDIT

* aucun refactor massif
* aucun changement d’architecture
* ne pas toucher aux routes serveur
* ne pas toucher à la logique d’accès physique réelle déjà valide
* ne pas ouvrir de nouveau chantier
* ne pas mélanger avec vision des villes / barracks / fortification
* ne pas inventer de nouveau flux joueur

OBJECTIF
Nettoyer les points d’accès UI dérivés ou résiduels afin que :

1. les services de ville passent par les chemins canoniques
2. les panneaux s’ouvrent via un canal unique
3. les vieux résidus morts soient supprimés
4. le code soit plus lisible sans changer le comportement validé

VÉRITÉ CANONIQUE À RESPECTER
A. Banque / Marché
Le point d’accès canonique doit être le menu d’action avatar.
Le joueur se place physiquement sur une ville, ouvre AvatarActionMenu, puis accède à Banque / Marché si les checks serveur l’autorisent.

B. Gestion territoire / fondation colonie
La gestion territoire et la fondation de colonie passent par UnifiedTerritoryPanel.
Ce flux ne doit pas être redoublé ailleurs.

C. Ouverture de panneaux
Le canal canonique d’ouverture doit être :
window.dispatchEvent(new CustomEvent('nova:open-panel', { detail: { panel } }))
puis résolution centralisée dans MedievalHUD via activeSection.

ÉTAT RÉEL AUDITÉ À PRENDRE EN COMPTE

1. MedievalHUD centralise déjà les panneaux avec activeSection + listener nova:open-panel.
2. AvatarActionMenu possède déjà les checks physiques banque / marché.
3. TileContextMenu expose encore des accès marché / banque = second point d’accès non canonique.
4. GameCanvas porte encore la logique hasMarket / hasBank liée à TileContextMenu.
5. AvatarActionMenu contient encore une branche morte found_colony.
6. MedievalHUD écoute encore openTerritoryPanel en plus de nova:open-panel.
7. GameCanvas passe encore onMoveRequest à AvatarActionMenu alors que ce mode n’est plus utilisé.
